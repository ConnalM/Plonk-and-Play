# WP8 S3g1 — bounded live TCP peer, host integration

S3g1 is the first bounded implementation of S3g, not completion of ESP/Wi-Fi integration. It connects the previously reviewed S3a–f components through a real byte stream and the existing Race Control/Noticeboard. The acceptance fixture uses actual Linux loopback TCP sockets, OpenSSL HKDF/HMAC and RAND, with deliberately short nonblocking reads/writes and a deterministic monotonic test clock. Nothing starts a listener or connects on an actual P&P device yet. No change to integrated firmware entry points, socket allocation, HTTP/SSE, Board configuration, SD or race algorithms.

## Ownership and bounded transport

The transport Peer is one exclusive connected stream attempt with one fixed outgoing and one fixed incoming frame buffer, bounded handshake record assembly and a session decoder. Exactly one nonblocking read OR write syscall per poll, at most one decoded frame or handshake transition, no drain loop, no application backlog and no dynamic frame allocation. The concrete platform Stream must map would-block to zero, EOF/error to negative, and never wait in the owner loop. Short reads/writes are normal. Send and partial-record deadlines retire the connection; do not scan for magic, replay a packet or retry a sporting action. No second transport or HTTP route.

One Core listener/one admitted peer (including an incomplete handshake) is the owner contract. Additional connections must be refused without touching an established or in-progress admitted peer. A fresh attempt is required after close. Host fixture exercises that policy; production listener/nonblocking connect/reconnect/backoff and exclusive peer ownership must implement it. A fresh Core boot epoch and long-lived LinkIds allocator, securely provisioned unique pair ID/PSK, CSPRNG, production crypto provider and safe key storage remain platform obligations. No default credential or unauthenticated replacement. PPTH exchange uses fixed reviewed record sizes, activates Core only after the entire Finish is sent, activates Taster only after verifying Finish. Directional MAC providers borrow the established handshake keys; close destroys decoder before wiping keys. Wire frame session/direction/strict sequence/MAC/shape validation still applies; failure closes.

Core port invokes S3f only on the existing Core owner after ordinary control/engine events. No request or result is put on the Browser Bus correlation namespace. Each valid command is submitted and, if queued, executed synchronously through the final authority/deadline fence; terminal gate/handler result is returned by session/ID. Invalid authentication, framing, or impossible nonterminal post-execution state closes; no command is executed before handshake and initial authenticated ping. TCP cannot know a remote disconnect before observing it: an already received admitted command may have executed, and missing reply is uncertainty, not rejection. Link close cancels remote knowledge, never the race.

Core sends an authenticated Pong before any initial snapshot, using receipt after authenticated decoding and send timestamp before sealing; queue delays stay inside the measured round trip. Core port collects the actual Noticeboard, readiness, proposal and context at the owner boundary, with committed preferences/revision only if supplied together by the owner. Publication is one complete snapshot. A result is sent before the subsequent requested snapshot, and the S3e conservative post-result receipt barrier still requires a sufficiently new sample and fresh physical neutral/touch. No locally extrapolated GO/timer. The Taster health client persists across socket attempts to retain stale/uncertainty semantics; an attempt cannot displace an already connected client.

Provisional engineering parameters: 2 s overall handshake, 250 ms partial-record/send deadline, ping every 1 s, Core closes after 2 s without valid ping, display target 50 ms, command expiry 250 ms beyond the conservative lower Core-clock bound. Refuse locally if that expiry is not safely beyond the upper bound. These are host policy values, not measured sporting tolerances or a promise of physical cadence. No queue of snapshots or commands. Renderer still owns validated button release, 700 ms PAUSE hold and confirmed abandonment; the link requires S3e fresh neutral/touch as an additional fence.

## Evidence and remaining S3g2/S4/S5 work

Host fixture covers wrong PSK, real split TCP handshake/frame writes and reads, one I/O call per poll, extra connection rejection without eviction, setup/START and post-result barrier using the real Core port, stale command after Browser takeover/release, lost START reply with same race/GO surviving reconnect, fresh session identity, periodic clock/snapshot refresh across GO, Browser takeover/release and fresh touch, write backpressure, authenticated payload corruption and stalled incomplete handshake. The test drives the actual Core owner handlers/engine but has no physical detectors, ESP scheduler, renderer, actual Browser HTTP traffic or Wi-Fi. Simulated clock advancement is deterministic; it is not a measured networking latency benchmark.

S3g2 must implement actual ESP/lwIP listener/client ownership, secure provisioning/provider and boot identity, reconnect/backoff, owner-loop scheduling and preference revision publication, the renderer bridge and physical touch integration, and confirm the generated Core socket/memory budget. The audited 10-socket setting cannot accommodate full existing HTTP capacity (10 including internal descriptors) plus listener/peer (at least 12 before margin); do not reduce Browser capacity or change SDK configuration in this PR. Measure heap/PCB/socket/coexistence and timing, including Taster off, stalled/reconnecting, SSE4 + ordinary requests, actual detectors, and verify both firmware builds. Keep production integration/physical acceptance open; no claim that host success satisfies it.
