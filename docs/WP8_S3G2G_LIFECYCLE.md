# WP8 S3g2g — coordinated Core/Taster connection lifecycle

Bounded source/host increment assembling the reviewed discovery selector, credential vault, Mbed TLS PPBS exchange and normal authenticated PPTH socket services. No firmware entry-point, SDK, Browser, physical Taster or SD changes. Real host TCP with simulated radio and protected-store contracts, not a production ESP owner or physical acceptance.

## Core owner

CoreOwner uses the supplied boot-loaded Core vault, persistent boot-scoped LinkIds, CorePort and trusted platform CorePolicy. Requires commissioned state, resource approval, reviewed socket budget and current AP network generation/address. Empty vault: one nonblocking AP-bound bootstrap listener, rate-limited acceptance, actual AP-path validation by CorePolicy, one exclusive candidate. Close the listener when reserving the candidate; no parallel TLS/PPTH listeners or additional Browser capacity. BootstrapSafety is independently evaluated throughout TLS and PPBS and must remain valid through this attempt's local commit. The existing Vault maintenance checks independently gate durable writes. Successful exchange destroys TLS and credential-exchange objects before constructing the paired service on the next poll. Paired vault: existing CoreService exclusively provides PPTH; bootstrap READY gate does not stop ordinary paired operation during racing. Additional connections cannot displace the paired peer. Resource/commissioning loss, network generation change and clock regression stop link ownership; incomplete local mutation enters Recovery. Nonempty invalid or revoked vault cannot automatically bootstrap. Existing race work must run before these operations; no change to sporting rules or Core independence.

The platform must implement live AP provenance, genuine race-idle/maintenance/resource conditions, reservation exclusion, secure key-store setup and actual scheduling. Bind to AP address alone does not establish interface provenance. No policy booleans accepted from wire. CorePolicy and vault Maintenance must refer to the same trusted owner. CorePort retains its existing execution and authority fences. Certificate generation, library steps and durable storage can take time: source bounds are not target CPU timing evidence. Boot allocator must not be recreated on link/network change. Actual ESP target build, heap/stack/sockets/PCB and concurrent Browser/physical race qualification remain open.

## Taster owner

TasterOwner loads discovery from the role-specific preloaded vault and protected hint; refuses incompatible/missing paired records. Radio is a narrow owner-thread interface to exclusive STA discovery and live association, including exact selected attempt/BSSID and generation, cancellation and quiescence. Host implements simulated radio; actual adapter must connect reviewed EspDiscovery to this interface and handle driver events, DHCP, interface validation and scan cancellation safely. The selector is the sole candidate authority: zero/multiple/one, explicit choice when needed, remembered Core only, no strongest-signal fallback. Owner supplies current choices and state for later renderer. Choice cancellation on commissioning loss never advances the clock artificially. Bounded association, dial, TLS, PPBS and initial PPTH/display synchronisation deadlines; retry uses existing exponential backoff, reset only on connected fresh authenticated display. No scan during an associated link. Radio.stop must retire stale asynchronous operations and prevent driver reconnect, or fail closed.

First use: selected live association, nonblocking TCP dial bound to STA address, exclusive TLS then PPBS, close/destroy bootstrap objects, start fresh ordinary TasterService using committed pair material. Remembered: matching vault/locator, ordinary PPTH only. Taster cannot expose READY/control until PPTH established, fresh authenticated display received and selector persistence succeeds. Internal health client, gated view and command entry points; outside Connected or on observed association change, suppress old lights/permission, mark cached data stale, reject commands. Existing touch-neutral, hold/confirmation, freshness and post-result barriers remain required; renderer still must enforce actual physical hold/release and confirmation rules. Network loss, commissioning loss or stale link retires service, cancels touch and reconnects to remembered locator; no automatic command replay. No raw access to health or service for the renderer. No customer codes/passwords/buttons.

## Limits and recovery

No automatic replacement or unsafe credential recovery introduced. If interrupted before local mutation and vault still empty, retry is permitted. If first use has mutated Taster vault but not completed locator persistence, or local commit is uncertain, enter Recovery; current paired hint/vault mismatch on reboot also fails closed. Core local uncertainty during exchange likewise enters Recovery for the instance. A lost Done may leave both stores paired; policy for safe reboot/reconciliation and explicit replacement remains separate. A Core that is still genuinely empty has no durable record of an interrupted remote-only mutation; no claim of distributed atomicity or safe automatic repair. Do not erase or overwrite credentials. First-use TLS still lacks independent identity verification (active impersonation/rogue first client possible); remembered PPTH remains authenticated.
