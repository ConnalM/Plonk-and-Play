# WP8 S3g2d — automatic Core discovery and remembered selection

Implements the first bounded increment of the [approved automatic connection UX](https://github.com/ConnalM/Plonk-and-Play/issues/14#issuecomment-7143384071). No codes, user passwords or pairing hardware. The selector and opt-in Taster-only ESP adapter are source/host work, not active firmware. No changes to Core AP/STA manager, existing Browser, racing, storage, build settings or devices. First-use authenticated bootstrap is deliberately still open.

## Discovery and selection

Use existing exact P&P AP SSID Plonk-and-Play, distinguish individual observed APs by full BSSID; no SSID change that affects existing SMUGLAND clients. A BSSID is a locator, not proof of Core identity or eligibility. Untrusted advertisements identify candidate networks only. Filter to exact SSID, validate unicast nonzero BSSID and valid 2.4 GHz channel. Multiple observations of identical BSSID on same channel collapse into one; conflicting channel, invalid candidate, scan error or overflow invalidates entire selection. At most eight distinct candidates, and ESP adapter refuses scan results larger than 64 rows rather than truncating to an apparent singleton. Bounds and 10-second choice lifetime are provisional engineering defaults, not frozen UI. Scan completeness means the driver completed a scan, not that every nearby radio was heard. No strongest-signal choice, automatic selection from incomplete scan, or fallback to other SSIDs.

Unremembered Taster: zero candidates yields NoneFound, one starts a candidate connection attempt, multiple yields Choose with stable BSSID ordering and scan token. The future renderer can display a distinguishable name/ID and signal strength without implying authentication. Choose by exact BSSID/current scan token, no stale row selection; expired choice requests rescan. A remembered Taster selects the stored BSSID even if other Cores are visible; if absent it waits rather than attaching to another system. Explicit owner-approved switch/reset/replacement UX and recovery remain open. The adapter does not scan during an associated/active link. Each attempt has non-reused token, selected locator, intent and expected pair ID; stale results cannot finish a different attempt. Clock regression fails closed.

## Association and authenticated identity

Opt-in ESP/Arduino adapter requests async scans on exclusive Taster STA only, collects bounded complete results, discards on cancellation, uses pinned BSSID/channel association request to existing open Core AP, disables automatic driver reconnect and credential persistence, verifies current AP via esp_wifi_sta_get_ap_info. No active Core or integrated firmware calls. Future owner must establish exclusive STA mode, disconnect and quiesce prior transport/association, schedule bounded scan/reconnect and connect deadlines, marshal Wi-Fi events, derive local/Core IP and network generation, and stop any connection after selector error. Scan timeout latches adapter fault until explicit owner reinitialisation, not a stale result. Association is NOT successful pairing, READY, or authority. No race command or renderer change here.

Remembered candidate must prove matching committed PPTH material through mutually authenticated link. Pair ID alone or BSSID alone is never an authentication credential. First use requires separately reviewed bootstrap, which must securely establish new material consistent with the approved trust-on-first-use limitation and preserve existing admission/race safeguards. Factory-provisioned pairs must include the matching locator record or go through explicit recovery; paired vault without locator is not treated as unpaired. The future owner calls authenticated only with current associated BSSID and pair ID after actual mutual PPTH authentication using committed vault material. Selector cannot itself verify proof or call that boundary from a network advertisement. Do not grant renderer control or mark connection complete until both authentication and locator persistence succeed. No sending PSK in plaintext, deriving from BSSID/SSID, silently evicting live Taster, or auto-revoking remembered credentials. A malicious first-use AP cannot be independently identified without an external trust anchor; actual bootstrap and replacement admission policy remain open.

## Remembered selection and failure

32-byte PPDH v1 record contains BSSID (6 bytes), pair ID (16 bytes), reserved zero, version, magic and CRC32 (accidental corruption only). No PSK. Separate core_hint key in existing dedicated protected pairing NVS partition, opt-in source adapter depends on already securely initialised EspStore. Persist after successful first-use authenticated PPTH, exact readback before Connected; no repeat write on remembered reconnect. Validate hint against active vault PairId at load. Missing/mismatched hint with paired vault, existing hint with empty vault, corruption, inaccessible storage, interrupted first-use credential mutation and readback failure fail closed; no silent fallback or auto-repair. Cross-record update is not atomic. Owner recovery must reconcile both records with transport stopped. For failure after possible credential mutation, owner must report uncertainty instead of claiming unchanged; only unchanged credentials permit retry. No secret export, settings reset, SD or new storage allocation. The owner must use Selector and transport together, not treat a state enum as security proof.

## Evidence and next work

Host test exercises deterministic discovery inputs, zero/one/multiple candidates, deduplication/order, no strongest-signal selection, scan overflow/error/conflict, stale choice/attempt tokens and timeout, remembered reconnect/wait, reboot and pair mismatch, locator write/readback failures, and clock regression. Authentication completion is an injected trusted owner event in this fixture, not a new cryptographic bootstrap; cumulative host PPTH and vault tests remain separate real cryptographic evidence. ESP scan, association and NVS adapter are uncompiled target source. Remaining: approved zero-interaction first-use bootstrap/admission/replacement technical design, concrete owner and protected storage wiring, network/retry lifecycle, renderer selection/status/touch integration, generated resource budget, separate target builds and actual radio coexistence/physical acceptance. No user-facing pairing security claim from discovery tests.
