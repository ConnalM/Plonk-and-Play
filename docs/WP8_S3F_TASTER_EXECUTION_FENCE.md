# WP8 S3f — Core execution fence (source and host acceptance)

This increment attaches the remote command gate to the real RaceControlModule handlers. No socket worker, production transport, network command or firmware build is enabled. All remote API calls are reserved to the single Core owner loop. Ordinary Race Control bus events and lifecycle transitions must be serviced before remote execution; the caller may not interleave unrelated owner mutations or invoke any remote method reentrantly. Only a successfully authenticated fresh session may be opened, and disconnect/takeover of the link must close the old session before opening another.

## Authority and execution order

PublishedControlAuthority now exposes a coherent standalone authority stamp under its existing short mutex. Generation starts at one, advances on every committed owner or connected-owner change and transport suspend/resume transition, and fails closed at exhaustion. Unrelated pending requests do not increment it. A retained but disconnected Master is not a connected controlling Browser. The Browser exposes this stamp and a final atomic claim through StartAuthority. Existing adapters without this capability deny remote execution by default. No Browser lease decision, HTTP endpoint or control token changes.

Race Control owns the session, one CommandGate, and a non-wrapping conservative revision. Context includes the actual session, Browser generation, revision, active race ID, proposal revision, lifecycle and permission. Revision advances on existing change notifications, proposal replacement, required-capability transitions and authority registration. This is conservatively broader than lifecycle alone. Unsupported/faulted/restarting states, Practice (active or proposed), missing proposal, unsupported lane count, absent/exhausted authority or connected Browser cannot grant remote permission.

At submission, the existing S3a gate validates the authenticated command. At owner execution it takes against a fresh context/time and again checks expiry and the Browser generation under the published authority mutex immediately before direct invocation. That successful atomic claim is the **linearisation point** against HTTP-task lease publication: a committed takeover or release before the claim invalidates even a command queued when no controller was connected; a transition after the claim is ordered after that admitted command. The claim does not hold the mutex during race processing, persistence or Bus publication. A fresh monotonic time check after the claim prevents an expired request executing after mutex acquisition. All actual sporting state mutation stays on the single Core owner, including Browser requests; those requests cannot overtake an admitted handler. This ordering contract must be verified in the live integration, not assumed for arbitrary cross-task direct mutation.

## Commands and result isolation

The remote API receives only the typed, validated S3a command, never a native Message from the network. It constructs a private stack request for exactly Setup, Start, Pause, Resume, confirmed Abandon or RaceAgain. Setup preserves inactive value and existing assignments and applies the fixed Taster finish policy. The real existing handlers still validate native readiness, setup, settlement and sporting lifecycle. Remote START always uses non-official standalone eligibility, never a Browser token or fixture impersonation.

To avoid a second queued dispatch gap or correlation collision, the owner synchronously invokes the actual handler rather than enqueueing a second Bus request. A private execution flag selects the standalone branch and captures the handler's terminal acceptance instead of broadcasting a synthetic RequestResult. It is not a new public native-message permission. Normal Browser/local Bus requests and their results remain unchanged; engine facts/operations and noticeboard notifications use the existing path. The S3a gate returns the result by authenticated session and 64-bit command ID, with no allocation from Browser/local 32-bit correlation numbers. Receipt/dequeue/claim is not acceptance; handler acceptance determines the terminal result. A lost result or disconnected session is uncertain, never retried. Gate rejection at final claim or final expiry is terminal Rejected; earlier gate validation may return specific Stale/Expired/Forbidden statuses. No new wire schema.

## Evidence and limits

Host tests drive the real Race Control handlers and committed authority publisher with simulated clock and lease changes (including takeover/release injected between take and claim), proposal/capability changes, expiry at dequeue and during claim, disconnect and fresh-session isolation, supported setup and all six actions, native pause settlement/confirmation, Practice denial, duplicate IDs and Browser result/official-record isolation. Engine settlement/completion are explicit host fixtures, not detector physics. Cumulative S3a-e and S2 local adapter tests remain. Source changes in Core/Race Control/Browser authority are intentional; no production activation or hardware acceptance is claimed. Live secure transport/provisioning, coherent snapshot publisher and consumer, scheduling, clock/touch integration, resource/coexistence and separate firmware builds remain open. Production owner-loop sequencing, real lease concurrency, physical race timing and actual SMUGLAND coexistence must be tested before release.
