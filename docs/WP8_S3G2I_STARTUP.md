# WP8 S3g2i — role startup composition and SDK compile boundary

Source integration only. Composes the reviewed ESP radio, network and Core policy, secure vault/hint store, EspCrypto, EspClock, real RaceControlPort and lifecycle owners into boot-lifetime role objects. Existing integrated setup/loop, accepted firmware, SDK config, partitions, display, Browser, SD and main branch remain untouched. This is not a production image: S4 must supply actual separate Core and Taster entry points, board selection, protected provisioning, and qualified facts.

## Startup order and ownership

Core: construct bootInstance with permanent existing race control, noticeboard and committed preference controller, trusted live RF entropy predicate, numeric dedicated port and measured budget. Before the existing AP/STA manager starts Wi-Fi, begin with an externally provisioned device-specific protected nvs_sec_cfg_t (caller wipes immediately). Install a single boot-lifetime Wi-Fi event hook, initialize PSA where required, secure-init dedicated pp_pair, load only genuine Empty or Paired vault after quiescence. No generated key, erase or fallback. Other states stop in Recovery. Preserve current Core Wi-Fi ownership; no competing manager. After normal input, control, engine, storage and Browser work each owner loop, poll with trusted local Approval facts. Default deny: commissioning, target qualification and exclusive ownership mandatory; budget must permit full existing Browser capacity plus link sockets. Core requires current AP and live entropy, constructs one random boot epoch and LinkIds once, keeps them across AP changes and withdrawal. Empty bootstrap also requires real READY/no-session Race Control plus owner-confirmed idle and exclusive borrowers; permission remains through this attempt's durable commit/Done, not arbitrary paired credential mutation. No runtime override from HTTP/wire. Paired service uses existing Race Control fences. Core normal work can continue with link disabled/faulted.

Taster: independent bootInstance owns exclusive STA, clock/crypto, protected storage and locator, maintenance and TasterOwner. No instantiated Core race/engine/Input/Browser/SD/records. Start while radio off; same protected storage requirements; register event hook before Wi-Fi. Begin only after vault load and matching remembered locator or genuine empty. Poll before rendering/input; scan may begin before RF entropy is available, but EspCrypto still requires the supplied live entropy check before and after random; initial durable mutation is only allowed for the exclusive Bootstrap state. Role remains Waiting on approval withdrawal; lifecycle gates discard stale authority/touch, no replay. Renderer will consume gated view/selection/physical input methods, not raw network or Core objects. Actual touch bridge and renderer status remain open.

RoleEvents registers one Arduino Wi-Fi event callback for one boot-lifetime role. Callback only forwards invalidation to the atomic revision; no socket, race, NVS or renderer work. No destruction or re-registration during boot. Target SDK callback registration result and event ordering must be verified; boot-instance and referenced object lifetimes must be enforced by actual entry points. The wrapper does not prove hardware entropy, secure keys, exclusivity or target qualification: those facts must come from the actual locally approved owner and may not be set true simply to make the link work.

## Committed preferences

Current Browser preference writes are on its HTTP task. Add a short mutex-protected value/revision publication after successful load or durable save/restore. No lock spans NVS writes. New RaceControlPort constructor uses a coherent copy; revision is actual memory generation, zero permitted for factory defaults, not an invented network counter. On storage-load failure no publication; failed/denied writes do not replace the last committed copy. Retain existing legacy current() and previous constructor paths for accepted integrated/fixture compatibility; this is not a general Browser concurrency refactor. Single writer after startup remains required.

## Actual SDK compilation — next milestone

Add guarded wp8_role_compile_probe.cpp to the established ESP-IDF project only when explicit CMake PP_WP8_ROLE_COMPILE_PROBE=ON. The probe references both startup compositions but is NEVER called by existing setup/loop/app_main; no runtime test or activation. Default CMake and PlatformIO builds do not include the probe path. It must be compiled against the actual ESP-IDF 5.5.5/Arduino and generated configuration, in a NEW disposable build directory, never bwp7welcome or any accepted tree. Use the pinned dependencies and environment from WP7_XIP_APPLICATION_BUILD_REFERENCE.md; do not modify sdkconfig.xip in place, copy it to the disposable build directory if needed. Example future authorised configuration: idf.py -B <new-dir> -D SDKCONFIG=<disposable-config-copy> -D PP_WP8_ROLE_COMPILE_PROBE=ON reconfigure; build ONLY the probe translation unit using its generated Ninja object target. Capture exact source commit, SDK/component versions, generated feature flags, compile command and diagnostics. No application image/flash/COM/SD access needed. If target build fails, identify exact feature/API incompatibility and propose smallest safe remedy; no speculative enabling of SDK features, changing the accepted config, lowering security or reducing Browser capacity. Source review and host tests do not compile the ESP header.

## Remaining gates

Actual SDK compile, real role entry points and board choice (S4), protected partition/device-key provisioning, live trusted entropy/idle/resource qualification and event ordering, safe interrupted-pairing reconciliation and replacement, actual renderer/physical touch, generated socket/heap/PCB coexistence budget (existing 10 sockets insufficient), physical acceptance (S5). First-use identity remains unverified. No automatic replacement. Host tests cover concurrent committed publication, denial/storage failure and reload; cumulative platform and real TLS/PPTH tests remain required.
