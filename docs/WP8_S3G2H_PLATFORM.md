# WP8 S3g2h — opt-in ESP platform adapters

Source increment connecting the reviewed lifecycle owners to ESP-IDF/Arduino Wi-Fi observation and local Core operating conditions. No firmware entry point or active role build, event registration, partition, SDK or hardware change. No claim of target compilation or radio/scheduler acceptance.

## Network generations and interface isolation

Boot-lifetime EventRevision receives STA start/stop/connect/disconnect/got/lost IP and AP start/stop invalidation events through permanent boot owner hooks; callbacks only increment an atomic saturating counter. Owner samples live state around the event revision; a changed revision during sampling invalidates the observation. NetworkEpoch increments for event changes (including a reconnect to the same IP), live readiness/address/interface changes or explicit invalidation; exhaustion fails closed. Event delivery/order and lifetime must be verified on target; register hooks before Wi-Fi startup and do not reconfigure drivers concurrently. Callback counters do not replace live association and interface queries.

EspCoreNetwork reads the existing open P&P AP configuration and the live WIFI_AP_DEF netif, IPv4 and implementation name. It does not start/stop the Core AP, scan, change external STA or touch HTTP/mDNS. EspRadio obtains the Taster's live selected association from EspDiscovery and WIFI_STA_DEF IP/gateway/netmask, verifying the gateway is on-link and distinct from the local address; the existing selector and PPTH still determine identity. No DNS or external Internet route. Network snapshots include the actual implementation name. All new lifecycle/paired listeners and dial sockets on ESP require SO_BINDTODEVICE before listen/connect, as well as the existing address bind; if the interface name or option is unavailable, do not use an IP-only fallback. Accepted sockets rely on the SDK fork's TCP listener netif filtering and accepted PCB inheritance, which must be checked and measured on target before resource approval. Host loopback fixtures use empty interface names, and do not claim physical interface isolation. Vendor API references: [ESP-NETIF](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32c2/api-reference/network/esp_netif_programming.html), [ESP lwIP socket definitions](https://github.com/espressif/esp-lwip/blob/2.2.0-esp/src/include/lwip/sockets.h), [ESP-IDF interface-bound HTTP listener example](https://github.com/espressif/esp-idf/blob/master/components/esp_http_server/src/httpd_main.c). These references support the source approach, not verification of the actual generated target build.

## Role-specific platform boundary

Core keeps the current AP/STA manager. EspCorePolicy implements both CorePolicy and Vault Maintenance: checks the real RaceControlModule READY/no defined active session, local owner-idle and borrower-quiescent assertions, protected storage/commissioning and resource qualification. Each owner iteration after normal race work prepares the current AP snapshot and local conditions; bootstrap revalidates current live AP generation, plus accepted socket endpoint. Race-idle/absence of engine/storage work, exclusivity of all credential borrowers and actual resource/scheduler approval must be provided by the same trusted Core owner (not an HTTP/wire field). Ordinary paired operation does not depend on bootstrap readiness. Existing sporting and Browser control logic untouched. Before boot vault load, set quiescence true only after verifying no service/borrower exists; leave mutation approval false until startup security and resource checks. The Taster uses LocalMaintenance with trusted commissioning/protected-store, exclusive STA service mode and borrower-quiescence facts; the existing lifecycle Admission independently rechecks association and reservation at each mutation. Role builds must not create competing owners or retain a credential reference across mutation.

EspRadio implements the Radio boundary using the reviewed EspDiscovery on exclusive Taster STA, Wi-Fi persistence off, RAM driver config and driver auto-reconnect disabled. Never on Core or integrated test role. Start only from radio off; association is pinned to the selected BSSID, live network sampled before each lifecycle operation; stop retires the discovery adapter and turns STA off, never turns off a Core AP/APSTA. No factory erase or credentials written to general Wi-Fi NVS. If a running asynchronous scan is cancelled or driver shutdown cannot be confirmed, latch a fault rather than adopting a delayed scan result. This conservative cancellation behaviour may require recovery; target driver event/drain ordering and normal reconnect/scan performance require actual acceptance. No background event callback performs network, persistence, transport or race work.
